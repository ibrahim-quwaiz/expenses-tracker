# الأشياء غير المنفذة / الناقصة

هذا ملخص لكل شيء اتناقشنا فيه أو له علاقة بالمشروع ولسا **ما تم تنفيذه**، أو تم استبعاده بقرار صريح. الرابط الحي: https://expense-api-nine-iota.vercel.app

---

## 1. شاشات/ميزات غير مبنية

| العنصر | الحالة | ملاحظة |
|---|---|---|
| **شاشة الميزانيات الشهرية** (Budgets UI) | غير مبنية | الـ Backend API جاهز بالكامل (`/api/budgets`, `/api/budget-status`) — بس ما فيه واجهة لإدارتها. في الإعدادات حاليًا رابط "قريبًا" غير فعّال |
| **حذف متجر** | غير موجود | يوجد `PUT /api/stores/[id]` للتعديل، لكن ما فيه `DELETE` — ولا فيه شاشة لإدارة/عرض قائمة المتاجر أصلاً |
| **تسجيل الدخول / المصادقة** | غير موجود إطلاقًا | لا يوجد نظام مستخدمين. أي شخص يملك رابط التطبيق يقدر يشوف/يضيف/يعدّل/يحذف كل البيانات بدون أي حماية |

## 4. قيود تقنية معروفة

| العنصر | القيد |
|---|---|
| ~~وقت العملية~~ | ✅ تم إصلاحه — `expenses.date` أصبح `timestamp` (تاريخ + وقت). التحليل يستخرج الوقت الفعلي من نص رسالة SMS إن وُجد، وإلا يستخدم الوقت الحالي. **ملاحظة:** تعديل حركة يدويًا (من شاشة التعديل) يحافظ على الوقت الأصلي، لكن حقل التاريخ بالتعديل تاريخ فقط بدون وقت — يعني ما تقدر تعدّل الوقت يدويًا حاليًا |
| **رفع شعار يدوي — الصيغ المدعومة** | PNG / JPEG / WEBP / GIF فقط، بحد أقصى 2 ميجابايت. **SVG غير مدعوم** بالرفع اليدوي (لكن مدعوم للشعارات التلقائية) |
| **التعرّف التلقائي على الشعارات** | ليس مضمون 100% — يعتمد على تعرّف Claude على العلامة التجارية ثم توفر شعارها في Wikimedia Commons أو كـ favicon. متاجر محلية غير معروفة تفشل بصمت (ترجع للأحرف الأولى) |
| **النشر التلقائي عند كل تحديث** | ربط GitHub بـ Vercel للنشر التلقائي فشل (يحتاج إذن يدوي من حسابك على GitHub) — كل تحديث بالكود يحتاج مني نشر يدوي (`vercel --prod`) |
| **البحث في شاشة الحركات** | يعمل على البيانات المحمّلة بالمتصفح فقط (بدون فهرسة أو Pagination من السيرفر) — مناسب لحجم استخدام شخصي، مو مصمم لآلاف السجلات |

## 5. ملاحظات معلّقة للمراجعة لاحقًا (دفعة وحدة)

| العنصر | التفاصيل |
|---|---|
| **تصنيف خاطئ لاتجاه بعض عمليات "إضافة الأموال"** | رسالة "إضافة الأموال عبر Apple Pay ... إلى: urpay" اتصنّفت "تحويل صادر" (transfer_out) بينما الصحيح "تحويل وارد" (transfer_in) — لأن التصنيف يعتمد على صياغة النص العامة، مو على أي حساب مسجّل عندنا فعليًا استقبل المبلغ. **الخطة:** ننتظر نجمع أمثلة مشابهة من كل الحسابات، نحصرها، ونعالجها دفعة وحدة (تعديل تعليمات الاستخراج في `lib/claude.ts` للتعرف على صياغات "إضافة أموال/شحن رصيد/Top-up" كتحويل وارد دائمًا) |
| **الرسوم المنفصلة ما تُجمع مع المبلغ الأساسي** | رسالة "حوالة محلية صادرة بـSAR 260 ... رسوم SAR 0.58" — الاستخراج حاليًا يطلع `amount` واحد بس، ما يميّز الرسوم كبند منفصل ولا يجمعها. **الحل المقترح (معلّق):** إضافة حقل استخراج اختياري `fee`، والمبلغ النهائي المحفوظ = `amount + fee` (مع ملاحظة تلقائية بالوصف توضح إن فيها رسوم مضافة) |

## 6. بيانات تجريبية متبقية

خلال الاختبار، أنشأت 3 متاجر تجريبية بأسماء واضحة تحتوي على "(تجريبي - يمكن حذفه)":
- العثيم (تجريبي - يمكن حذفه)
- بنده (تجريبي - يمكن حذفه)

ما فيه واجهة أو زر لحذفها حاليًا (بسبب نقطة #1 أعلاه — "حذف متجر" غير موجود).

**الخلاصة**: التطبيق شغّال بكامل الوظائف الأساسية (تسجيل مصروفات يدويًا أو عبر SMS بعدة رسائل، تصنيفات، تقارير، شعارات متاجر تلقائية، أيقونة للشاشة الرئيسية)، لكن ناقصه شاشة الميزانيات وأي حماية دخول — وهذي أهم نقطتين لو تبي تكمل.
